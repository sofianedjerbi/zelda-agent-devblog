Devlogan AI learning to finish any Zelda, on one Mac

Goal: an AI that finishes any top-down Zelda, on one Mac, with local models only. It must learn skills, not memorise a game. The brain is the same for every Zelda; each game needs a small adapter that reads its memory (position, room map, health, items).

Where it stands, honestly

The goal is an agent that knows how to play any Zelda. It does not yet. Two things are measured: the real games, which are the goal, and a set of generated dungeons, which are practice. A critic I asked to attack this page found the practice number oversold; this version is the corrected one.

What is learned: the order in which the agent takes its options. It plays thousands of training dungeons, takes a random option a quarter of the time, and each choice is scored by what followed: a new room, a key, a way opened, the dungeon solved, death. A small network learns that score. What is still mine: the list of options itself, the filters, the hands that carry a goal out, the sword rule. So the fair sentence is: a learned ordering of my options beat my ordering, {{ site.data.unseen.pct }}% against {{ site.data.unseen.hand }}%, inside this world.

One harder test inside this world: a mechanic the agent never met while learning. Trained on dungeons with no lever, then tried on dungeons that have one, it solves 73 of 113 (80 when trained with levers, 52 with my ranking). Trained with no web, on dungeons with a web: 141 of 228 (167 and 109). Most of what it learned carries to a lever, about half to a web.

Limits of this practice set: the ranking is now trained only on gains a player can see (a room never seen, a key, something new in the bag, a shut passage open, the dungeon solved, death) - with the simulator's own record of progress it scored 78%, without it 77%; not every generated dungeon can be solved after a wrong move (I opened one that could not): on the set I may look at, 364 of 400 were solved at least once in ten tries, so at least 91% can be; one try solves about 80%, and only 240 are solved every time - a good part of a failure is bad luck with enemies; an earlier version of this page said 80% with looks that were the same in every dungeon - nine of those points were memorised looks.

Fighting

The whole fighting skill is one rule: when an enemy that can hurt Link is in the sword's line, strike. It is not learned and it does not dodge. I picked it with a fast test: 240 saved dangerous moments outside and 240 in the dungeon, 150 actions each.

In full games the rule cut game overs from 6.2 to 4.4 per 10,000 steps and hits from 33.8 to 24.1 (now 5.0 and 27.2). What does not work yet: dodging (see below), rooms with many enemies, and the boss (0 of 16 games reach it). Trained reflexes and backing off were both tried and rejected, see IDEAS.

Shots and movement

The agent avoided enemies but walked into their shots. I measured it: outside, at least 24 of 85 hits come from a shot (a rock), not from touching an enemy. The agent saw a shot only as a dot, with no speed and no direction.

It can now see movement: where each object is, minus where it was 8 frames earlier. Anything fast and straight that will reach Link within 4 steps is a shot, and he steps out of its line. Nothing in the code says what a shot looks like.

Neither is a gain, so both stay off. Seeing movement is not enough: a shot lives 3 to 12 decisions and the agent decides only every 16 to 48 frames. My fast fight test said deciding twice as often would halve the deaths (22, 49, 62 game overs of 240 when deciding every 8, 16, 32 frames); full games did not agree. Next: one death outside, frame by frame, to see what really hits Link.
